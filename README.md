# maxHack — виртуальные лабораторные работы (ВЛР)

Комплекс для проведения школьных лабораторных работ по физике в мини-приложении
мессенджера MAX: учитель собирает лабораторный стенд из электрических приборов,
настраивает журнал замеров и выдаёт работу классу, ученик проводит опыт, снимает
показания, выполняет расчёты и отправляет работу на проверку.

---

## 1. Назначение решения

Решение закрывает полный цикл лабораторной работы в школе без физического
оборудования:

- **учителю** — собрать стенд из приборов, задать журнал замеров, опубликовать
  работу для всех или выдать конкретным классам, проверить сданные журналы,
  выставить оценку и скачать журнал в Excel;
- **ученику** — открыть работу, провести опыт на интерактивном стенде (регулируя
  параметры приборов), записать показания, заполнить расчётные столбцы, написать
  вывод и отправить работу;
- **школе** — вести классы, переводить их на следующий год, связывать учителей
  с учениками.

Предметная область реализованного стенда — **электричество**: закон Ома,
последовательная цепь, измерительные приборы, колебательный контур.

## 2. Основной пользовательский сценарий

1. Учитель открывает бота в MAX и регистрируется командой `/reg` (роль «Учитель»).
2. Бот даёт кнопку «Открыть лабораторию» — запускается мини-приложение внутри MAX.
3. Учитель в каталоге нажимает «Создать» и собирает работу:
   - **Основное**: название, предмет, краткое описание, цель, методические указания;
   - **Стенд**: добавляет приборы из палитры, расставляет их и соединяет проводами
     (выход прибора → вход другого);
   - **Журнал**: выбирает столбцы, которые приборы заполнят автоматически, и
     добавляет столбец, который считает ученик;
   - **Классы**: выбирает «Классам» (с указанием классов) или «Всем».
4. Учитель нажимает «Опубликовать». Работа появляется в каталоге, а ученикам
   выданных классов бот присылает уведомление.
5. Ученик регистрируется в боте (`/reg`, роль «Ученик», указывает школу и класс),
   открывает мини-приложение и видит работу в разделе «Частные» или «Публичные».
6. Ученик нажимает на работу и выбирает режим:
   - **Рабочий режим** — журнал и вывод уйдут учителю;
   - **Тестовый режим** — потренироваться, никуда не отправляется.
7. На стенде ученик регулирует параметры (напряжение источника, сопротивление,
   ёмкость, индуктивность, диапазоны приборов), нажимает «Старт», смотрит
   показания приборов, нажимает «Записать» — строка добавляется в журнал.
8. Заполняет столбцы, которые считает сам, пишет вывод и нажимает «Завершить» →
   «Отправить учителю».
9. Учитель в разделе «Проверка» открывает сдачу, видит журнал, график зависимости,
   автоматическую сверку расчётов, читает вывод ученика, пишет комментарий и
   ставит оценку («Принять» / «На доработку»).
10. Журнал можно выгрузить файлом Excel (`attempt-<id>.xls`).

## 3. Состав и архитектура решения

```
┌──────────────┐   initData (подпись MAX)   ┌───────────────────┐
│  MAX         │ ─────────────────────────► │  front (SPA)      │
│  мессенджер  │ ◄───────────────────────── │  React 19 + Vite  │
│  + бот       │   кнопка «Открыть»         │  порт 8080 (nginx)│
└──────┬───────┘                            └─────────┬─────────┘
       │ Long Polling (maxapi)                        │ REST /api/v1
       │                                              │ Bearer JWT
┌──────▼──────────────────────────────────────────────▼─────────┐
│  back — FastAPI + SQLAlchemy (async) + maxapi, порт 8000       │
│  ─ авторизация по подписи initData, выдача JWT                 │
│  ─ работы, классы, попытки, проверка, экспорт в Excel          │
│  ─ бот: регистрация, список работ, уведомления                 │
│  ─ миграции goose при старте контейнера                        │
└──────────────────────────────┬─────────────────────────────────┘
                               │ asyncpg
                     ┌─────────▼─────────┐
                     │  PostgreSQL 15    │  том pgdata
                     └───────────────────┘
```

|---|---|---|
| `front/` | React 19, TypeScript 5.9, Vite 8, Zustand, `@maxhub/max-ui` | Мини-приложение: каталог работ, конструктор стенда, симулятор, журнал, проверка сдач |

**Ключевые части фронтенда:**

- `front/src/sim/` — библиотека приборов и решатель схемы: `components/library.tsx`
  (8 электрических приборов), `solver.ts` (порядок обхода цепи, проход измерения,
  проверка совместимости величин);
- `front/src/physics/quantity.ts` — единицы измерения, группы величин, перевод в СИ;
- `front/src/features/stand/StandCanvas.tsx` — полотно стенда: приборы, клеммы,
  провода, анимация тока;
- `front/src/features/stand/StandBuilderScreen.tsx` — конструктор (4 шага);
- `front/src/features/stand/StandRunScreen.tsx` — прохождение работы учеником;
- `front/src/features/attempts/` — проверка сдач учителем, график, экспорт.

**Ключевые части бэкенда:**

- `back/src/api/` — `auth.py`, `labs.py`, `attempts.py`, `classrooms.py`,
  `export.py`, `links.py`, `components.py`, `deps.py`;
- `back/src/core/security.py` — проверка подписи `initData` (HMAC-SHA256, срок

- `back/src/bot/` — команды бота и уведомления;
- `back/src/database/migrations/migrations/` — 5 SQL-миграций goose;
- `back/docker-entrypoint.sh` — ожидание базы, накат миграций, запуск uvicorn.

### Приборы лабораторной

| Прибор | Клеммы | Регулируемые параметры | Что даёт |
|---|---|---|---|
| Источник питания | выход напряжения, вход обратного провода | напряжение 0…24 В | напряжение в цепь |
| Амперметр | вход, выход | диапазон 0,1…20 А | силу тока по закону Ома |
| Вольтметр | вход, выход | диапазон 1…100 В | напряжение источника |
| Резистор | вход, выход | сопротивление 1…100 Ом | ток `I = U / R` |
| Лампа | вход, выход | номинальное напряжение 1…24 В, мощность 1…100 Вт | цвет от бледно-жёлтого (от 1 В) до красного (на номинале) |
| Конденсатор | вход, выход | ёмкость 1…2000 мкФ | замкнутую цепь |
| Катушка индуктивности | вход, выход | индуктивность 1…5000 мГн | замкнутую цепь |
| Колебательный контур | два входа (L, C) | — | частоту `f = 1 / (2·π·√(L·C))`, π = 3,142 |

Величины разделены на группы (электрические, время, тепловые, геометрия,
механика, оптика). Соединять можно только величины одной группы и только
**выход → вход**; на полотне выход помечен зелёным, вход — синим.

## 4. Запуск всех локальных компонентов одной командой

Из **корня репозитория** (там лежит `docker-compose.yml`):

```bash
docker compose up -d --build
```

Команда собирает и поднимает `db` (PostgreSQL 15), `api` (FastAPI) и `web` (nginx
с собранным мини-приложением). Схема базы накатывается автоматически при старте
контейнера `api`.

Адреса после запуска:

| Что | Адрес |
|---|---|
| Мини-приложение | http://localhost:8080/ |
| API | http://localhost:8000/api/v1 |
| Документация API (Swagger) | http://localhost:8000/api/v1/docs |
| Проверка готовности | http://localhost:8000/healthz |
| PostgreSQL | `localhost:5433` |

## 5. Необходимые параметры окружения

Минимум для локального запуска — ничего настраивать не нужно, всё имеет значения
по умолчанию. Для полноценной работы бота и корректной подписи сессий нужны:

| Параметр | Обязателен | Значение по умолчанию | Зачем |
|---|---|---|---|
| `BOT_TOKEN` | для бота | `mock_bot_token` | подпись `initData` из MAX и работа бота |
| `JWT_SECRET_KEY` | в проде | `change_me_in_production` | подпись сессий мини-приложения |
| `MAX_BOT_NAME` | для бота | `vlr_bot` | ник бота: из него собирается кнопка «Открыть лабораторию» |
| `MINIAPP_URL` | для бота | `http://localhost:8080/` | адрес мини-приложения для уведомлений |
| `DEBUG` | нет | `false` | `true` открывает вход без подписи MAX (только для локальной отладки) |
| `POSTGRES_*` | нет | `postgres/postgres/vlr_db` | доступ к базе |

Перед первым запуском создайте файл окружения бэкенда:

```bash
cp back/.env.example back/.env
```

## 10. Описание работы с данными

**СУБД:** PostgreSQL 15, том `pgdata`. Схема накатывается миграциями goose
(`back/src/database/migrations/migrations/`) при старте контейнера `api`.

| Таблица | Хранит |
|---|---|
| `users` | пользователи MAX: `max_user_id`, ФИО, роль, город, школа, класс, предмет |
| `classrooms` | классы школы, уникальны по паре «школа + номер» |
| `labs` | лабораторные работы: автор, название, предмет, описание, цель, методичка, видимость, `math_model` (стенд и журнал), `journal_columns`, `noise_percent`, `max_rows` |
| `attempts` | попытки: ученик, работа, режим (`test`/`work`), статус, `result_data` (замеры, ответы, вывод), оценка, комментарий, время старта и завершения |
| `lab_assignments` | выдача работ классам |
| `teacher_student_links` | связи учитель — ученик |
| `components` | пользовательские компоненты (служебная таблица) |

**Стенд работы** хранится в `labs.math_model` как JSON:

```json
{
  "version": 2,
  "stand": {
    "components": [{ "id": "c1", "key": "source", "x": 22, "y": 26, "params": { "voltage": 12 } }],
    "links": [{ "id": "l1", "from": { "component": "c1", "terminal": "right" },
                          "to":   { "component": "c2", "terminal": "left" } }]
  },
  "journal": [{ "key": "c2-out", "label": "Сила тока", "unit": "А", "source": "auto",
                "bind": { "component": "c2", "port": "out" }, "precision": 2 }]
}
```

**Поток данных при сдаче работы:** ученик нажимает «Завершить» → фронтенд создаёт
попытку `POST /api/v1/attempts/` → отправляет журнал и вывод
`POST /api/v1/attempts/{id}/finish` → API сохраняет `result_data` и уведомляет
учителя в MAX → учитель выставляет оценку `POST /api/v1/attempts/{id}/review`.

**Персональные данные:** хранятся ФИО, школа, город, класс, ник и идентификатор
MAX. Токены: JWT живёт 7 суток, хранится в `localStorage` мини-приложения.
Пароли не используются — вход только по подписи MAX.

**Резервное копирование:**

```bash
docker compose exec db pg_dump -U postgres vlr_db > backup-$(date +%F).sql
```

**Экспорт:** журнал попытки выгружается методом
`GET /api/v1/attempts/{id}/export.xls` как XML-таблица Excel.

## 11. Порядок работы с тестовыми данными

Тестовых данных в репозитории нет — база создаётся пустой, схема накатывается
миграциями. Данные появляются двумя способами.

**Способ 1 — «боевой» путь:** учитель и ученик регистрируются в боте MAX и
создают работу через интерфейс. Наиболее близко к реальному сценарию проверки.

**Способ 2 — служебный вход (быстрая проверка API):** при `DEBUG=true` доступен
`POST /api/v1/auth/dev-login`, который выдаёт токен для указанного
`max_user_id` и создаёт пользователя при первом обращении:

| Роль | `max_user_id` | Как выглядит в системе |
|---|---|---|
| Учитель | 900002 | «Локальный Разработчик», роль `teacher` |
| Ученик | 900001 | «Локальный Разработчик», роль `student` |

Рекомендуемый порядок подготовки тестовых данных:

1. Войти как учитель (`dev-login`, `role: teacher`).
2. Заполнить профиль: `PATCH /api/v1/auth/me` — школа и город.
3. Войти как ученик (`dev-login`, `role: student`), указать школу и класс
   (`class_number`) — ученик автоматически попадёт в класс.
4. Создать работу `POST /api/v1/labs/` со стендом из источника питания,
   резистора и амперметра.
5. Выдать работу классу ученика `POST /api/v1/labs/{id}/assign`.

Очистка тестовых данных — полное пересоздание окружения:

```bash
docker compose down -v      # удаляет том pgdata вместе с данными
docker compose up -d --build
```

## 12. Пошаговый сценарий проверки

Ниже — проверка, которая проходит на чистой машине с Docker. Обозначения:
`API=http://localhost:8000/api/v1`, `WEB=http://localhost:8080/`.

### Шаг 0. Запуск

```bash
cp back/.env.example back/.env
sed -i 's/^DEBUG=false/DEBUG=true/' back/.env    # только для локальной проверки
docker compose up -d --build
```

### Шаг 1. Готовность сервисов

```bash
docker compose ps
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8000/healthz   # 200
```

**Ожидаемо:** `db` — `healthy`, `api` — `healthy`, `web` — `Up`; `/healthz`
возвращает `200` (метод читает таблицу `users`, то есть схема накатана).

### Шаг 2. Приложение открывается

Откройте `http://localhost:8080/` — загружается мини-приложение «Лабораторные
работы». Вне MAX доступен ручной вход: профиль → «Роль для проверки» → «Учитель».

### Шаг 3. API и документация

```bash
curl -s http://localhost:8000/api/v1/openapi.json | head -c 200
```

**Ожидаемо:** JSON OpenAPI 3.1, 18 путей. Интерактивная документация —
`http://localhost:8000/api/v1/docs`.

### Шаг 4. Вход и создание работы

```bash
TOKEN=$(curl -s -X POST $API/auth/dev-login \
  -H 'Content-Type: application/json' \
  -d '{"max_user_id":900002,"role":"teacher"}' | python3 -c 'import json,sys;print(json.load(sys.stdin)["access_token"])')

curl -s -X POST $API/labs/ -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"title":"Закон Ома","visibility":"public",
       "math_model":{"version":2,"stand":{"components":[],"links":[]},"journal":[]}}' \
  | head -c 200
```

**Ожидаемо:** первый вызов возвращает `access_token`, `user.role = "teacher"`;
второй — `201` и созданную работу с `id`.

### Шаг 5. Стенд в конструкторе

В мини-приложении: «Создать» → «Стенд» → добавить «Источник питания»,
«Амперметр», «Резистор» → соединить клеммы: выход источника → вход амперметра →
вход резистора. На полотне видны провода; при попытке соединить два входа
появляется объяснение «Обе клеммы — входы…».

### Шаг 6. Расчёт схемы

Соберите цепь источник → резистор, задайте напряжение 12 В и сопротивление
10 Ом. Ожидаемая сила тока — **1,2 А** (закон Ома). При сопротивлении 4 Ом —
**3 А**; при двух резисторах по 10 Ом — **0,6 А**.

### Шаг 7. Колебательный контур

Добавьте катушку 100 мГн, конденсатор 100 мкФ и колебательный контур, соедините
их клеммы. **Ожидаемо:** контур показывает **50,32 Гц** по формуле Томсона.

### Шаг 8. Прохождение работы учеником

Войдите учеником, откройте работу, нажмите «Старт», затем «Записать» — строка
появляется в журнале; заполните расчётный столбец, напишите вывод, нажмите
«Завершить» → «Отправить учителю».

### Шаг 9. Проверка работы учителем

Под учителем откройте «Проверка» → сдачу: виден журнал, график зависимости,
отметки автоматической сверки, вывод ученика. Нажмите «Принять», введите
комментарий. **Ожидаемо:** сдача переходит в статус «Принято», ученику приходит
уведомление в MAX (если задан настоящий `BOT_TOKEN`).

### Шаг 10. Экспорт журнала

```bash
curl -s -o journal.xls "$API/attempts/1/export.xls?token=$TOKEN"
file journal.xls
```

**Ожидаемо:** файл `journal.xls` — XML-таблица Excel, открывается в Excel и
LibreOffice.

### Шаг 11. Автоматические проверки кода

```bash
cd front && npm ci && npm run typecheck && npm test && npm run build
cd ../back && pip install -r requirements.txt && pytest tests/unit -v
```

**Ожидаемо:** типизация без ошибок, 75 тестов фронтенда и 13 тестов бэкенда
проходят, сборка успешна.

## 13. Примеры ожидаемого поведения системы

**Успешные сценарии**

| Действие | Ожидаемый результат |
|---|---|
| `GET /healthz` при живой базе и накатанной схеме | `200 {"status":"ok","database":"ready"}` |
| `GET /healthz` при отсутствии таблицы `users` | `503`, в логах предупреждение о недоступной базе |
| `POST /auth/` с корректной подписью MAX | `200`, выдан токен, `is_new_user` соответствует ситуации |
| `POST /auth/` с чужой подписью | `401 «Невалидная подпись initData»` |
| `POST /auth/` с `initData` старше 24 часов | `401` |
| `POST /auth/` с `role: "admin"` | `422` — роль ограничена значениями `student`/`teacher` |
| Создание работы учеником | `403 «Доступ разрешен только для учителя»` |
| Чтение чужой приватной работы учеником | `403 «Работа вам не выдана»` |
| Экспорт журнала чужой работы учителем | `403 «Это работа другого учителя»` |
| Завершение попытки с полем `grade` | `200`, но оценка **не** применяется: её ставит только учитель через `/review` |
| Повторная выдача уже выданной связи учитель — ученик | `409 «Связь уже существует»` |
| Соединение выхода источника с входом резистора | Провод создан, ток рассчитан |
| Соединение двух входов | Отказ с текстом «Обе клеммы — входы…» |
| Соединение напряжения и сопротивления | Несовместимо: разные группы величин, отказ с указанием единиц |
| Лампа при 0,5 В | Не светится |
| Лампа при 1 В | Бледно-жёлтый цвет |
| Лампа при номинале (12 В) | Красный цвет |

**Ошибочные ситуации и реакция**

| Ситуация | Поведение |
|---|---|
| Бэкенд не запущен | Мини-приложение показывает «Нет связи с сервером» с кнопкой «Повторить»; соединение не кешируется |
| Приложение открыто вне MAX и `DEBUG=false` | Экран «Приложение открыто вне MAX» с подсказкой открыть лабораторию кнопкой в боте |
| Токен истёк | `401`, мини-приложение просит открыть приложение заново |
| База недоступна при старте API | Контейнер не стартует, в логе `[entrypoint] база не ответила за 90 секунд` |
| Каталог миграций отсутствует | Контейнер падает с `[entrypoint] ОШИБКА: нет каталога миграций …` вместо старта на пустой схеме |
| `MINIAPP_URL` указывает на внешний стенд | Предупреждение в логе; при `ALLOW_FOREIGN_MINIAPP=true` — информационное сообщение |

## 14. Известные ограничения

1. **Вход через MAX работает только внутри MAX.** Какие-либо пароли отсутствуют:
   в браузере вне мессенджера доступен только ручной выбор роли при `DEBUG=true`.
2. **`DEBUG=true` открывает вход без подписи MAX.** Допустимо только для локальной
   проверки; в проде обязателен `DEBUG=false`.
3. **Модель цепи — последовательная.** Амперметр и вольтметр рассчитывают
   показания по суммарному сопротивлению собранной цепи, параллельные ветви и
   распределение токов не моделируются.
4. **Реактивные элементы идеальны.** Конденсатор и катушка не считают реактивное
   сопротивление и сдвиг фаз: они замыкают цепь и передают номиналы контуру.
5. **Колебательный контур считает только частоту** по формуле Томсона с π = 3,142
   (по условию лабораторной); затухание и добротность не рассчитываются.
6. **В лабораторной только электрические приборы.** Механика, теплота и оптика из
   библиотеки удалены вместе с соответствующими разделами.
7. **Параметр источника переименован** (`emf` → `voltage`). В работах, сохранённых
   до изменения, он прочитается как значение по умолчанию (12 В) — такую работу
   нужно открыть в конструкторе и сохранить заново.
8. **Автоматическая сверка расчётов поддерживает закон Ома и производные от него**
   формулы (сопротивление, скорость, площадь, удельная теплоёмкость); для
   произвольных формул используется ручная проверка учителем.
9. **Оценку ставит только учитель.** Ученик не может выставить себе оценку.
10. **Бот работает через Long Polling**, вебхуки не настроены; для больших нагрузок
    потребуется перейти на webhook.
11. **Миграции выполняет контейнер API при старте.** При нескольких репликах API
    запускать их параллельно нельзя — потребуется отдельный шаг миграций.
12. **CORS по умолчанию открыт для всех источников** (`["*"]`) — для прода следует
    указать конкретный домен.
13. **Экспорт журнала** — XML-таблица Excel (`.xls`); формат `xlsx` не формируется.
14. **График зависимости в проверке сдач** строится по первым двум автоматическим
    столбцам журнала; произвольный выбор осей не предусмотрен.
15. **Нет ограничения частоты запросов** на стороне API и нет ролей администратора
    школы: классы создаёт учитель, перевод классов на следующий год выполняет
    учитель своей школы.

## 15. Порядок остановки и повторного запуска решения

**Остановить, сохранив данные:**

```bash
docker compose stop          # контейнеры остановлены, данные и сеть сохранены
```

**Запустить снова:**

```bash
docker compose start         # быстрый повторный запуск
# или
docker compose up -d         # с учётом изменений compose-файла
```

**Полностью удалить контейнеры, сохранив базу:**

```bash
docker compose down
```

**Удалить всё вместе с данными (чистый старт):**

```bash
docker compose down -v
docker compose up -d --build
```

**Пересобрать после изменений в коде:**

```bash
docker compose up -d --build          # пересборка изменившихся образов
docker compose build --no-cache api   # принудительно пересобрать API
```

**После перезагрузки сервера** стек поднимается сам: у всех сервисов задано
`restart: unless-stopped`, а миграции накатываются внутри контейнера API. Проверить
состояние:

```bash
docker compose ps
docker compose logs --tail=40 api     # ждём: база доступна → миграции применены → uvicorn
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:8000/healthz
```

Если `docker compose` сообщает `KeyError: 'ContainerConfig'` — установлен
docker-compose v1; нужен плагин Compose v2 (`docker compose`, не `docker-compose`).
